# Upgrade to Umbraco 19

From Umbraco Commerce `[18.0.0, 18.999.999)` (CMS 18) to Umbraco Commerce `19.0.0-beta.1` (CMS `19.0.0-beta1`, tag `release-19.0.0-beta1`).
Branch `topic/19.x/cms-19-upgrade` → PR into `release/19.0.0`, cut from `main` (`c5010ae`).

**Targets CMS release:** `release-19.0.0-beta1`, via Umbraco Commerce `19.0.0-beta.1` (MyGet `umbracoprereleases`). The package's own version is `19.0.0-beta.1`.

The package depends only on `Umbraco.Commerce.Core` and `Stripe.net`, never on `Umbraco.Cms.*` directly, so the CMS breaking changes reach it only through Commerce. Commerce's own v19 inventory (Core repo, `docs/upgrades/v19.md`) is the source for those.

## Inventory

| Change | Source | Since | Where it hits us |
|---|---|---|---|
| .NET 10 → .NET 11 | CMS `release-19.0.0-beta1:Directory.Build.props`; Commerce 19.0.0-beta.1 targets net11.0 | beta1 | `Directory.Build.props`, test `.csproj` |
| .NET SDK 11.0.100-rc.3.26522.148, pinned with `rollForward: disable` (same as Core) | Core `global.json`; umbraco/Umbraco.Build#10 (merged 30-10-2026) | beta1 | `global.json` |
| Umbraco.Commerce.Core `[18.0.0, 18.999.999)` → `[19.0.0-beta.1, 19.999.999)` | Commerce `release-19.0.0-beta.1` | beta.1 | `Directory.Packages.props` |
| `Umbraco.Commerce.Core.Models.Customer` clashes with `Stripe.Customer` (CS0104) | Compile against Commerce 19.0.0-beta.1 (type exists since Commerce 18.1; Stripe main still resolved 18.0.x) | beta.1 | `StripeCheckoutPaymentProvider.cs:738` |
| Commerce removals in v19 (legacy payment route, `PaymentProviderAttribute(alias, name, ...)` ctors, `PaymentProviderBase.DefaultSettings`, refund v1/v2, `Orderline*` renames) | Core `docs/upgrades/v19.md` "Breaking changes for consumers" | beta.1 | None: provider uses `[PaymentProvider("stripe-checkout")]` and `ctx.Urls`, no hard-coded payment URLs |
| Obsolete APIs | CS0618 build on v18 (none) and on Commerce 19.0.0-beta.1 (none) | – | None |
| Backoffice | `wwwroot/umbraco-package.json` registers one `localization` extension | – | No change: `localization` type unchanged in 19 |
| Package validation baseline 18.0.0 can't validate a net11 package | Core task 10 | beta.1 | `Directory.Build.props`: validation off, baseline 19.0.0, re-enabled once 19.0.0 is on NuGet (uc-post-release) |
