# Upgrade to Umbraco 19

From Umbraco Commerce `[18.0.0, 18.999.999)` (CMS 18) to Umbraco Commerce `19.0.0-beta.1` (CMS `19.0.0-beta1`, tag `release-19.0.0-beta1`).
Branch `topic/19.x/cms-19-upgrade` → PR into `release/19.0.0`, cut from `main` (`c5010ae`).

**Targets CMS release:** `release-19.0.0-beta1`, via Umbraco Commerce `19.0.0-beta.1` (MyGet `umbracoprereleases`). The package's own version is `19.0.0-beta.1`.

The package depends only on `Umbraco.Commerce.Core` and `Stripe.net`, never on `Umbraco.Cms.*` directly, so the CMS breaking changes reach it only through Commerce. Commerce's own v19 inventory (Core repo, `docs/upgrades/v19.md`) is the source for those.

## Breaking changes for consumers

- Requires Umbraco Commerce 19 (.NET 11).
- Stripe.net 53.1 (was 50.0): sites that reference Stripe.net themselves move with it (System.Text.Json instead of Newtonsoft, null-means-unset option semantics, `PaymentMethodTypes` options removed, .NET 5/6/7 dropped).
- Behaviour: the "Payment Method Types" setting is now sent as `allowed_payment_method_types`, which Stripe treats as a filter on the methods it would offer, not a fixed list: a method that is disabled in the Dashboard or not eligible for the currency or country is silently dropped instead of failing the session. A setting of only commas (e.g. `", ,"`) now falls back to `card` instead of sending an empty list.
- Merchants' webhook endpoints can stay on their current Stripe API version: the provider reads only the event's id, type and object id, then refetches the object through Stripe.net.

## Follow-ups

- Live test-mode smoke on a v19 site before 19.0.0 final (needs Stripe test keys; the unit tests can't run these):
  1. Payment-mode Checkout with the default `card`, finalized by `checkout.session.completed`.
  2. "Payment Method Types" set to e.g. `card,ideal`: the hosted page shows exactly those, no 400; also one method that's disabled or ineligible (now dropped silently).
  3. `create=paymentIntent` callback (Elements): `clientSecret` returned.
  4. Manual capture: authorize, capture, status Captured, card country from `latest_charge`.
  5. Cancel an authorization; partial and full refund, incl. refund-then-cancel-subscription.
  6. Subscription session with recurring items: `latest_invoice.payments`, subscription cancel on refund.
  7. `payment_intent.succeeded` and `review.closed` from a webhook endpoint on an older API version (clover or dahlia).
  8. Repeat order with no billing country: customer update still sends `metadata[billingCountry]=` (same body as Stripe.net 50), clearing that key.
- `StripeCheckoutPaymentProvider.cs` has mixed line endings (pre-existing).
